Two CLIs cover the two starting points:

- **`npx solvapay@latest init`** — add SolvaPay to an **existing** project, in TypeScript, Python or Go
- **`npm create solvapay@latest`** — scaffold a **new** project from a template (`npx create-solvapay@latest` is equivalent)

## Prerequisites

- Node.js 22 or later, to run the CLI (also for Python and Go projects)
- A project directory where you want to add SolvaPay (for `solvapay init`)

## Run setup

From your project root:

```bash
npx solvapay@latest init
```

## What this command does

When you run `npx solvapay@latest init`, the CLI:

1. Detects the project's language and package manager from the files in the folder (table below)
2. Opens your browser to sign in to SolvaPay Console
3. Writes `SOLVAPAY_SECRET_KEY` to `.env`
4. Ensures `.env` is listed in `.gitignore`
5. Installs the SolvaPay SDK for that language
6. Verifies your secret key with SolvaPay and saves `SOLVAPAY_PRODUCT_REF`
7. Prints the next steps

| Found in the folder | Language | Installs |
| --- | --- | --- |
| `package.json` | TypeScript | `@solvapay/server`, `@solvapay/core` and `@solvapay/auth` with npm, pnpm or yarn (by lockfile) |
| `uv.lock` | Python | `uv add 'solvapay==<version>'` |
| `poetry.lock`, or `[tool.poetry]` in `pyproject.toml` | Python | `poetry add 'solvapay==<version>'` |
| any other `pyproject.toml`, or `requirements.txt` | Python | Nothing: it prints the `python -m pip install` command, because it doesn't choose your interpreter |
| `go.mod` | Go | `go get github.com/solvapay/solvapay-sdk/go@<version>` |

Python and Go versions are pinned exactly, to the newest stable release. The Python and Go SDKs read environment variables, not `.env`: load `.env` when the app starts (python-dotenv in Python, a few lines in Go) or export the variables.

When the folder has files for two languages (a Next.js app beside a Python API), or none, `init` asks which language. With `--yes`, or when no one is at a terminal, it stops and asks for `--language` instead of guessing; it creates a `package.json` only with `--language ts`.

| Flag | What it does |
| --- | --- |
| `--language ts\|python\|go` | The project's language |
| `--features mcp,agents,web` | What you use SolvaPay for: the `solvapay[...]` extras in Python, or `@solvapay/mcp`, `@solvapay/agents` and `@solvapay/react` in TypeScript |
| `--product <ref>` | Saves this product instead of asking |
| `-y`, `--yes` | Skips the prompts |

## Files the CLI creates or updates

| File | What changes |
| --- | --- |
| `package.json` | Created only with `--language ts` in a folder without one |
| `.env` | Adds or updates `SOLVAPAY_SECRET_KEY` and `SOLVAPAY_PRODUCT_REF` |
| `.gitignore` | Adds `.env` if needed |
| Lockfile (`package-lock.json`, `uv.lock`, `poetry.lock`, `go.mod`) | Adds the SolvaPay SDK |

## Check a project or a running server

```bash
# The key, the product and its plans, and that the SDK is the newest release
# (npm, PyPI or the Go module proxy). Prints the exact upgrade command.
npx solvapay@latest doctor

# A running MCP server in any language: OAuth discovery, the tool list and the
# sign-in challenge. Add --credentials-file <file with an accessToken> to also
# check the paywall and the account tool.
npx solvapay@latest verify https://my-server.example.com/mcp
```

## Add stack-specific packages

`solvapay init` installs base server packages. Add framework packages based on your stack:

- Next.js: `@solvapay/next` and usually `@solvapay/react`
- React: `@solvapay/react` (and `@solvapay/react-supabase` if using Supabase)
- MCP Server: `@solvapay/server` is already installed by init

Use [Installation](./installation) for exact package commands.

## Scaffold a new project

To start from scratch, use the `create-solvapay` scaffolder instead of `init`:

```bash
# Paid MCP server (Cloudflare Worker + embedded checkout widget)
npm create solvapay@latest my-mcp-app -- --type mcp

# Generate MCP tools from an OpenAPI spec
npm create solvapay@latest my-api-mcp -- --type mcp --openapi ./openapi.yaml

# Paid MCP server in Python (uv) or Go, with a Dockerfile for any container host
npm create solvapay@latest my-mcp-app -- --type mcp --language python
npm create solvapay@latest my-mcp-app -- --type mcp --language go

# Next.js + Auth0 starter with SolvaPay customer linkage
npm create solvapay@latest my-app -- --type next-auth0
```

### Template types

| `--type` | What you get |
| --- | --- |
| `mcp` | A paid MCP server on Cloudflare Workers: `@solvapay/mcp` server factory, OAuth bridge, and an embedded checkout widget built with `@solvapay/react/mcp`. With `--openapi <url\|path>`, tools are generated from your API spec; with `--no-openapi` you get a placeholder paid tool. With `--language python` or `--language go`: a server on the Python or Go SDK with one paid tool, one free tool with a cap, tests, `.env.example`, a Dockerfile and Dependabot (from scratch only; `--openapi` is TypeScript only) |
| `next-auth0` | A Next.js App Router starter wired for Auth0: `@auth0/nextjs-auth0` session handling, `createAuth0AuthMiddleware` from `@solvapay/next/middleware`, and the `externalRef` customer linkage set up for you. `--auth auth0` is a shortcut for this type |

Useful flags: `--product <ref>` to pre-select a product, `-y` / `--non-interactive` for CI,
`--skip-install`, `--skip-init` (the scaffolder runs `solvapay init` at the end unless you
skip it), and `--offline` (pin `@solvapay/*` to the versions the scaffolder ships with instead of
npm's latest; without it, a failed registry lookup stops the scaffold). Run `npm create solvapay@latest -- --list-types` to see available templates.

## Re-run setup safely

You can run `npx solvapay@latest init` again at any time.

If `SOLVAPAY_SECRET_KEY` already exists, the CLI asks whether to overwrite it:

- Choose `y` to replace it with a new key
- Choose `n` to keep your current key

## Scope

These commands are the recommended setup paths for SDK integration.

If you are using Managed MCP, you do not need either CLI flow.

## Stale scaffolder cache

`@latest` is required, but `npx` can still reuse a cached `create-solvapay` tarball.
Every run prints `create-solvapay vX.Y.Z` — check that banner against the
[published version](https://www.npmjs.com/package/create-solvapay). If it lags:

```bash
npx clear-npx-cache
npm create solvapay@latest my-mcp-app -- --type mcp
```
