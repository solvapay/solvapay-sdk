## Overview

npm packages in this monorepo publish on **independent per-package semver** via
[Changesets](https://github.com/changesets/changesets). There is no shared
version line and no auto-patch-bump on push to `main`.

- **Preview** — push to `dev` runs [`.github/workflows/publish-preview.yml`](../.github/workflows/publish-preview.yml) and ships snapshot versions on the `@preview` dist-tag.
- **Stable** — push to `main` runs [`.github/workflows/publish.yml`](../.github/workflows/publish.yml). Pending changesets open a "Version Packages" PR; merging that PR with an empty `.changeset/` publishes to `@latest` and pushes tags.
- **Non-npm trains** — Rust, Go, Python, and Ruby each have their own workflow. None of those are driven by Changesets.

Authoring rules (bump levels, `workspace:^` peers, `pnpm changeset status --verbose`) live in [`CONTRIBUTING.md`](../CONTRIBUTING.md) and [`.cursor/rules/monorepo-versioning.mdc`](../.cursor/rules/monorepo-versioning.mdc). Do not duplicate them here.

## Versioning

[`.changeset/config.json`](../.changeset/config.json) is the source of truth:

| Field | Value | Meaning |
| --- | --- | --- |
| `baseBranch` | `main` | Stable publish branch |
| `linked` | `[]` | Explicitly **no** shared version line |
| `access` | `public` | npm public packages |
| `updateInternalDependencies` | `patch` | Workspace dep bumps are patches |
| `ignore` | examples and demo apps | Those packages never publish |

`.changeset/config.json` does **not** ignore `@solvapay/server-wasm`, and that package is not `"private": true`.

## Authoring a change

```bash
pnpm changeset
pnpm changeset status --verbose
```

Pick patch / minor / major per package. Internal peer dependencies use
`workspace:^` so a peer patch does not cascade a major. See CONTRIBUTING for the
full table.

## Preview (`dev`)

Pushing to `dev` fires `publish-preview.yml`. That job produces Changesets
snapshot versions and publishes them to the `@preview` dist-tag.

The unpublished-dependency registry gate (`check-release-dryrun --registry`)
does **not** run in `publish-preview.yml`.

## Stable (`main`)

Pushing to `main` fires `publish.yml` in two modes:

1. **Pending changesets** — `changesets/action` opens or updates a "Version Packages" PR (commit `chore: version packages`).
2. **Empty `.changeset/` after that PR merges** — the same workflow publishes to `@latest` and pushes matching git tags.

Identity for the Version Packages PR is the `solvapay-release-bot` GitHub App
(`RELEASE_APP_ID` / `RELEASE_APP_KEY`). Org policy blocks `GITHUB_TOKEN` from
opening PRs (`can_approve_pull_request_reviews: false`). npm auth is `NPM_TOKEN`.

Manual `workflow_dispatch` defaults to dry-run (`dry_run: true`): gates plus
`changeset status` and `pnpm -r publish --dry-run`, no `NPM_TOKEN`, no
`changesets/action`. Push-to-`main` is always the real path.

### Pre-publish gates, in order

These steps run in `publish.yml` before `changesets/action`:

1. `pnpm install --frozen-lockfile`
2. `pnpm exec tsx tools/repo/check-release-dryrun.ts --registry`
3. `pnpm deps:check`
4. `pnpm build:packages`
5. `pnpm test`
6. `pnpm validate:fetch-runtime`
7. Deno workspace gate: `pnpm --filter @example/supabase-edge-mcp validate:workspace`

After a real publish, `tools/repo/verify-npm-publishes.mjs` confirms each
package landed on npm.

### The unpublished-dependency gate

[`tools/repo/lib/release-dryrun.ts`](../tools/repo/lib/release-dryrun.ts) refuses
to publish a package whose production `workspace:*` dependency is neither in the
same batch, nor already on npm, nor on `UNPUBLISHED_DEP_ALLOWLIST`.

The single allowlisted entry is `@solvapay/server-native`: the nine
`@solvapay/server-native-*` platform packages are not wired for npm publish
(deferred at Step 39). Empty reasons are rejected — this is an explicit
deferral, not a silent skip.

This registry probe runs **only** in `publish.yml`. It does not run in
`publish-preview.yml` or `ci.yml`. That gap is named, not hidden. Locally,
`pnpm checks:release-dryrun` is offline (no `--registry`).

## Non-npm release trains

These workflows default to dry-run. A real publish requires a
`workflow_dispatch` input or a `solvapay-<lang>-v*` tag. Changesets do not
drive them.

| Workflow | Destination | Trigger |
| --- | --- | --- |
| `publish-rust.yml` | crates.io | `workflow_dispatch` / `solvapay-rust-v*` |
| `publish-go.yml` | Go module tag (`solvapay-go`) | `workflow_dispatch` / `solvapay-go-v*` |
| `publish-python.yml` | PyPI | `workflow_dispatch` / `solvapay-python-v*` |
| `publish-ruby.yml` | RubyGems | `workflow_dispatch` / `solvapay-ruby-v*` |

## Why npm can diverge from this workspace

`@solvapay/server@2.2.1` was published from `main` commit `c6e6617a` on
2026-08-27. The `sdks/typescript/*` layout has never existed on `main`
(`ee190801` is not an ancestor of that commit).

The published tarball is a faithful build of `main`, **not** a packaging defect:
`files: ["dist"]` and the tsup `native` entry are both correct. This branch has
simply not shipped.

## What the first release from this branch must contain

`@solvapay/server-wasm@0.1.0` must reach npm **before, or in the same batch as**,
`@solvapay/server`. The hard production dependency at
`sdks/typescript/server/package.json` (`"@solvapay/server-wasm": "workspace:*"`)
is rewritten to a literal version at publish time and currently 404s on npm.

[`.changeset/server-wasm-first-release.md`](../.changeset/server-wasm-first-release.md)
exists for that first publish.
[`.changeset/phase4-paywall-parity.md`](../.changeset/phase4-paywall-parity.md)
carries the paywall parity work.

`@solvapay/server-wasm` is neither `"private": true` nor in the Changesets
`ignore` list. It is still unpublished. Documenting the ordering constraint is
not the same as publishing it.
