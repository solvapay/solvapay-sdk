## Overview

npm packages in this monorepo publish on **independent per-package semver** via
[Changesets](https://github.com/changesets/changesets). Rust, Python, Ruby, and
Go share a lockstep version owned by the private sentinel
[`@solvapay/release-train`](../internal/release-train/package.json).

- **Preview** — dispatch [`.github/workflows/publish-preview.yml`](../.github/workflows/publish-preview.yml) with `dry_run=false`. One dispatch previews all five ecosystems. Pushing to `dev` does not publish.
- **Production** — merge work into `main`, then merge the "Version Packages" PR that [`.github/workflows/publish.yml`](../.github/workflows/publish.yml) opens.

**The canonical spec is
[release-and-publishing.md](./contributing/release-and-publishing.md).** It
covers both channels end to end: the channel matrix, per-ecosystem registries
and version grammars, every pre-publish gate, click-by-click trusted-publisher
setup, and the ordered enablement checklist. Everything below is either a
pointer or detail that spec does not own.

Changeset authoring rules (bump levels, `workspace:^` peers,
`pnpm changeset status --verbose`) live in
[`CONTRIBUTING.md`](../CONTRIBUTING.md) and
[`.cursor/rules/monorepo-versioning.mdc`](../.cursor/rules/monorepo-versioning.mdc).

## Versioning config

[`.changeset/config.json`](../.changeset/config.json) is the source of truth:

| Field                        | Value                           | Meaning                                          |
| ---------------------------- | ------------------------------- | ------------------------------------------------ |
| `baseBranch`                 | `main`                          | Stable publish branch                            |
| `linked`                     | `[]`                            | npm packages stay independently versioned        |
| `privatePackages`            | `{ version: true, tag: false }` | Sentinel is versioned, never published or tagged |
| `access`                     | `public`                        | npm public packages                              |
| `updateInternalDependencies` | `patch`                         | Workspace dep bumps are patches                  |
| `ignore`                     | examples and demo apps          | Those packages never publish                     |

`.changeset/config.json` does **not** ignore `@solvapay/server-wasm`, and that
package is not `"private": true`.

## Authoring a change

```bash
pnpm changeset
pnpm changeset status --verbose
```

Pick patch / minor / major per package. Internal peer dependencies use
`workspace:^` so a peer patch does not cascade a major.

## Hold the pending npm changesets

`.changeset/` carries a large backlog, including a `major` of `@solvapay/core`
and the first `@solvapay/server-wasm` release. Merging that work to `main` opens
a Version Packages PR that will publish **all of it** when the PR merges. Review
that PR as a conscious release, not a side effect of the train work.

## Why npm can diverge from this workspace

`@solvapay/server@2.2.1` was published from `main` commit `c6e6617a` on
2026-08-27. The `sdks/typescript/*` layout has never existed on `main`
(`ee190801` is not an ancestor of that commit).

The published tarball is a faithful build of `main`, **not** a packaging defect:
`files: ["dist"]` and the tsup `native` entry are both correct. This branch has
simply not shipped.

## What the first release from this branch must contain

`@solvapay/server-wasm@0.1.0` must reach npm **before, or in the same batch as**,
`@solvapay/server`. The hard production dependency at
`sdks/typescript/server/package.json` (`"@solvapay/server-wasm": "workspace:*"`)
is rewritten to a literal version at publish time and currently 404s on npm.

[`.changeset/server-wasm-first-release.md`](../.changeset/server-wasm-first-release.md)
exists for that first publish.
[`.changeset/phase4-paywall-parity.md`](../.changeset/phase4-paywall-parity.md)
carries the paywall parity work.

The same constraint applies to `@solvapay/server-native`. The next
`@solvapay/server` release has no JavaScript fallback on Node, so shipping
`server` / `server-wasm` without the eight native platform packages gives Node
consumers a main entry that throws on first call. Both publish workflows now
build and publish those eight ahead of the Changesets batch, gated by
`verify-native-platform-publishes.ts` and
`check-release-dryrun.ts --assert-no-local-paths` — see
[release-and-publishing.md](./contributing/release-and-publishing.md#the-native-platform-packages).

Platform and ABI coverage: [platform-support.mdx](./platform-support.mdx).
