# SDK binding hardening

Seven changes, none architectural. The repo already has the parts that are hard to retrofit — a Rust core with per-language sibling crates, generated bindings with `git diff --exit-code` drift gates, a cross-language fixture corpus, artifact gates that test the packed package, `SOLVAPAY_ABI_VERSION`, and `native_build_info` for two facades. What follows finishes the edges.

Two items from the original review are **deliberately out of scope** here: publishing a Released/Preview/Unreleased tier table for the facades, and writing down what `SOLVAPAY_ABI_VERSION 2` promises. Both are decisions rather than implementation, and neither blocks anything below.

A useful first PR is 1 + 6 + the two panic tests: three items closed, no dependencies, nothing that can break a publish.

## 1–3. Ruby

`rb-sys = { version = "*" }` is the only wildcard in the tree. For a payments SDK that means the extension a customer compiles next month is not the one CI tested. The lockfile resolves 0.9.128; pin it there.

The magnus upgrade is smaller than the 3,658-line ext suggests. The 0.8 breaking surface is: `old-api` no longer a default feature (deprecation warnings on the global, handle-less API), `FString` removed, `RArray`/`RHash` `FromIterator` moved behind `old-api` in favour of `Ruby::ary_from_iter` / `Ruby::hash_from_iter`, MSRV 1.65. This binding is already on the handle-based API — `magnus::init` takes `&Ruby`, `error.rs` calls `Ruby::get()`, and there is no `FString` or `collect::<RArray>()` anywhere in it. So expect a version bump plus whatever `-Dwarnings` turns up. Crucially, `register.rs` is generated by dto-gen, so if a pattern does change it changes once in the template.

The dock deferral is recorded twice — the `publish-ruby.yml` header and, in more detail, `sdks/ruby/scripts/dock-build.sh`, whose header names the actual root cause: the `rbsys/*:0.9.128` images ship a Ruby 4.0 host with incomplete 3.3 toolchains. The magnus 0.8 bump removes one blocker but may not be the only one, so item 3 starts by validating a current dock image before touching the workflow. If it works, `rb-sys-dock` cross-compiles the platform gems instead of building on native hosts, which is what adds the two musl rows. The transport is `rustls-tls` with no OpenSSL in the graph, which removes the usual worst part of dock builds.

## 4. Python matrix

`abi3-py39` means each new row is one wheel covering 3.9–3.14, so the two missing rows are cheap. Alpine on arm64 is a normal payments-backend container today, and `musllinux_1_1` currently exists only for x86_64.

## 5. Panic containment

`docs/contributing/error-handling.md` states unwind containment as a repo-wide property ("`catch_unwind` at every FFI edge"). Sync edges do satisfy it in every native facade — capi, python, node-native and ruby all wrap them. What does not literally satisfy it: the two wasm facades (`panic = "abort"`, documented in-crate), and the async client methods — `native_client.rs`'s 45 `#[napi]` fns, ruby's `client.rs`, python's `client.rs` — which inherit napi-rs / magnus / pyo3 boundary behaviour. That may well be sufficient (napi-rs intercepts panics, pyo3 raises `PanicException`, magnus ≥0.8 raises `fatal`), but it is currently undocumented and untested, and unwinding into V8 or CRuby takes down the customer's worker rather than ours. One constraint the magnus behaviour imposes: since 0.8 a magnus-raised `fatal` cannot be rescued even by `rescue Exception`, so the Ruby probe test must assert that *our* `catch_unwind` envelope fires before magnus's boundary does.

The workspace lints (`unwrap_used`, `expect_used`, `panic` all denied) stop *our* panics, not a dependency's. So the test is what matters: a feature-gated panicking op, and one assertion per facade that it raises rather than aborts, run against the built artifact. The `*-binding-artifacts` gates currently only check artifact filenames, so they gain an install-and-run step (node can reuse `node-clean-install-native`, which already installs the packed package).

## 6. Build-info parity

`native_build_info()` → `{version, coreSha}` plus a version-skew test exists for Python and Ruby and is the single best debugging affordance in the repo: it answers "which core is actually installed" without a bisect. Node, wasm, capi and Go should have the same three lines. `sdks/go` is the interesting one, because the embedded `solvapay_core.wasm` and the facade can in principle disagree — the publish workflow's staleness check prevents that at build time, and the stamp makes it observable at runtime.

## 7. Ops-by-facade coverage

`gen:verify` proves the generated bindings match the manifest; `binding-symbols.snapshot.json` already carries per-op names for ts/py/rb/go/rust/c. What nothing currently answers is which ops a given facade does *not* expose, and why. Emitting that as a committed matrix with a required reason per gap — and diffing it in CI — turns eleven facades' worth of tribal knowledge into a reviewable file. ICU4X does exactly this with `tests/missing_apis.txt` and requires it triaged to empty before a release.

## 8. wazero ADR

Running a WASI guest under wazero for the Go facade is genuinely unusual — nothing comparable in the twenty SDKs surveyed does it; OpenDAL's purego is the nearest neighbour and still calls a native library. Both halves of the trade need to be written down before someone proposes "just use cgo," and before someone else assumes `sdks/capi` can be shared with Go.
